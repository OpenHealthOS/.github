# Contributing to OpenHealthOS

Thank you for helping build open, interoperable healthcare technology.

## Before you begin

1. Read [OPENHEALTHOS_CONTEXT.md](OPENHEALTHOS_CONTEXT.md) for the
   organization-wide direction and architecture.
2. Check existing issues and discussions before starting new work.
3. Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Contribution types

We welcome bug reports, documentation improvements, tests, features,
integrations, research experiments, and architecture proposals. Use the
appropriate issue form to start a substantial proposal before investing in a
large implementation.

## Development expectations

- Keep changes focused and document user-visible behavior.
- Include tests when changing executable code.
- Do not add patient data, credentials, secrets, or other sensitive data to
  issues, pull requests, tests, or examples.
- Use interoperable, vendor-neutral approaches where practical; see the
  context document for architecture principles.
- Record major, cross-repository architectural decisions as proposals or ADRs
  before implementation.

## Pull requests

1. Create a focused branch from the repository's default branch.
2. Explain the problem, solution, and validation in the pull request template.
3. Resolve review feedback constructively and keep the branch current.
4. Ensure applicable automated checks pass before requesting review.

By contributing, you agree that your contributions may be distributed under
this repository's license.
