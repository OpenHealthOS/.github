# OpenHealthOS Governance

## Purpose

This document describes how organization-wide decisions are made. It
complements, but does not replace, repository-specific maintainer practices.

## Roles

| Role | Responsibilities |
| --- | --- |
| Contributors | Propose, implement, review, and improve project work. |
| Maintainers | Review contributions, manage releases, and enforce community standards. |
| Organization maintainers | Set cross-repository direction and approve organization-wide decisions. |

## Decision-making

Maintainers seek consensus through issues, pull requests, and discussions.
For significant architectural, security, or cross-repository changes, the
proposal should document motivation, alternatives, interoperability impact,
security and privacy considerations, and rollout implications.

When consensus is not reached, the responsible maintainers make the decision
and record the rationale in the relevant issue, pull request, or architecture
decision record. The organization context is authoritative for ecosystem
direction; repository documentation governs implementation intent.

## Participation

All participants must follow the [Code of Conduct](CODE_OF_CONDUCT.md).
Maintainer access and responsibilities may change based on sustained,
constructive contributions and the needs of the project.
